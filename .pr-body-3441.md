## Summary

PR #3435 widened the 0509#3330 +x gate to every job in `deploy-production.yml` but tokenized each `run:` string after filtering it with `startsWith("./scripts/")`. A `run: |` block whose script invocation sits on line 2 or later escaped the +x check entirely. Hardening only — the live check in the issue found zero such lines today (all 8 `./scripts/` refs are single-line; the two multiline blocks use `node scripts/…`).

## Change

- New `collectDeployWorkflowScriptTokens` helper tokenizes per line (`run.split("\n")` then `line.split(/\s+/)`), so a `./scripts/…` token on any line of any `run:` block is caught.
- New `expectScriptExecutable` helper keeps the gate's exact exit-126 assertion message.
- New test: a parsed multiline `run: |` block with the invocation on line 2 yields the token, and the +x assertion fires with the exit-126 message for a non-executable file and passes for an executable one. Existing gate behavior on today's workflow is unchanged (same 5 tokens, all executable).

Verification:

- Observe-to-close drill: appended a `run: |` step calling `./scripts/multiline-probe.sh` (chmod 644) on line 2 of the workflow, uncommitted — the gate FAILED with `./scripts/multiline-probe.sh lost its +x bit — the Actions checkout runs it as ./scripts/multiline-probe.sh and dies with exit 126 (0509#3330)` (the old net passed this drill silently). Drill files reverted, suite re-run green.

run-proof: test-only change; the runs above are the proof (changed-mode suite green before and after the drill revert, drill failure reproduced then closed).

net-positive-because: the gate's one job is to catch a lost +x bit before production does; without the per-line tokenizer a whole class of multiline run blocks passes the gate silently, so the net must get wider even though today's workflow adds no lines.

loose-ends: none — single-file test hardening, no product code touched.
