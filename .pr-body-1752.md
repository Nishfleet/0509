## Summary

Deploy production was red from 2026-09-06T02:08Z on `browser_hydration_error:console`
with app code byte-identical to the last green run (`99134b994`). Every red run ended with
`launch:readiness:predeploy failed` but printed no line naming the mismatching page, message
or test — there was nothing to bisect from. This PR closes the capture half of that gap so
any future red run names the surface.

### Capture the surface (was impossible to bisect)

The `reactHydrationError` annotation recorded only the source (`console`/`pageerror`). The
release hydration bridge now records a `reactHydrationErrorDetail` annotation alongside it
carrying the console message text (first 300 chars, secret-like substrings redacted), the
page URL and the test title. The manifest reporter parses the detail back onto each manifest
entry and writes the first one to the job log, so a red run names the failing surface in the
deploy-readiness JSON and the job log without opening an artifact. The strict gate,
`HYDRATION_ERROR_PATTERN` and `E2E_RELEASE_STRICT` are unchanged; no retry, no allowlist.

### Surface fix already landed

The mismatch's root cause was Playwright 1.63's trace recorder calling `page.screenshot()`
during action phases, which injects `caret-color:transparent` as an inline style on every
input before React hydration completes, producing a false `browser_hydration_error:console`.
The fix — turning trace `screen` snapshots off — was reproduced and landed in main by
#1774 (merged PR #1798) while this issue was open. This PR is the instrumentation that makes
that kind of red run name itself; it does not re-ship the already-merged config change.
