## ErrorBoundary treats HTTP 410 as a server fault — Gone responses render 'Something broke on our side'

Adds an explicit HTTP 410 branch to the root `ErrorBoundary` so a deliberate
Gone (empty offer timeline, issue #1309 retire path) renders an honest
"not stored yet" shell instead of the generic server-fault copy.

### What changed

- `app/root.tsx` — new `error.status === 410` branch in `ErrorBoundary`.
  - Unadorned 410: heading "This page is gone", body "This page is not stored
    yet." / "If you were looking for a competitor, search for it.", with
    "Back to Five to Nine" and "Open search" actions.
  - Brand-context 410 (data carries `domain` + `brandName`): body names the
    brand and points at `/search?q=<domain>` and `/ads/<domain>`.
  - The 410 branch never emits "Something broke on our side".
- `app/routes/timeline.$domain.tsx` — the empty-ledger throw now carries
  `{ domain, brandName }` via `Response.json` so the boundary can name the
  brand. The decision to return 410 on an empty ledger is unchanged (#1309).
- `tests/error-boundary-410.test.ts` — renders the boundary with status 410
  and asserts the fault string is absent and a next-action control is present
  (both the unadorned and brand-context cases).
