# Customer-readiness remediation

Last updated: 2026-07-17

## Commercial loop under test

- Working buyer: an India-based D2C growth lead tracking 3–10 Meta-heavy competitors.
- Paid loop: landing page → trustworthy live proof → saved watchlist → useful recurring brief → Starter checkout.
- This is a working hypothesis, not validated product-market fit. Customer interviews, pilot use, willingness to pay, and a real payment remain external proof gates.

## Rules for this backlog

- Work as complete vertical customer journeys. A journey is not done when only its screen or only its backend is fixed.
- Never present demo, broader, stale, or unverified data as live verified proof.
- Track implementation and release separately. `workState` is `fixed`, `verified`, `blocked`, `external proof required`, or `rejected`; `releaseState` is `fixed-candidate`, `locally-verified-on-fingerprint`, `review-blocked`, or `external-proof-required`. Local work never inherits a release state from another fingerprint.
- Every journey has four independent gates: **A** candidate implemented; **B** deterministic responsive E2E release proof on the exact fingerprint using synthetic/internal tenants and controlled provider/inbox replay; **C** exact deployed internal canary tied to Worker version/config identity with cleanup; **D** external market validation from target buyers. Release readiness means A–C pass. D governs only desirability, retention, ROI, and willingness-to-pay claims; lack of customers never blocks A–C.
- A blocked slice stays unintegrated and undeployed; record its exact branch, fingerprint, and missing gate, then continue with the next independent journey.
- Minimal Nish-owned live email, checkout, subscription, refund, cancellation, and production-provider canaries are authorized after clean local/review gates. Protected-main merge, push, and production deployment are also authorized, but only for one immutable candidate after every required local, browser, accessibility, provider, migration, restore, security, review, safe-deploy, cleanup, version/config, and rollback gate is current and green. Customer outreach, customer data, unrelated provider mutations/spend, and privacy-affecting analytics remain separately gated.

All four frozen candidates are outside every active owner boundary: the parked reliability candidate plus frozen Journey 3, 4, and 5 candidates.

Any accepted finding is deduplicated into the canonical set, repaired by the authoritative owner, fully re-proved on a replacement fingerprint and restarts the sequence at the first affected lens. No heavy suites overlap. Post-consolidation repeats the complete sequence on the new fingerprint before the existing Fable/Codex/current-research consensus audit.

### Execution and handoff protocol

- Root owns product architecture, shared files, ownership changes, cross-slice semantics, candidate freeze/fingerprint, serialized heavy gates, exact-candidate review, current rendered proof, provider proof, and the final classification. Specialists never silently widen their slice.
- Every slice moves through `assigned` → `running` → `returned` → `integrated` or `rejected` → `closed`. A returned handoff is not accepted until root inspects its diff, resolves interactions, and reruns the combined contract.
- Every handoff records owner, state, exact changed files, validation and result, blockers/assumptions, and do-not-touch boundaries. Idle slots are reused only for genuinely independent work; ownership, shared-file, provider, or heavy-gate collisions take precedence over utilization.
- Heavy type generation, full tests, production builds, browser suites, provider canaries, and exact-candidate reviews run serially. Root monitors live agents and local resource pressure and closes or reclaims orphaned work without duplicating edits.
- A test, browser, review, or provider claim belongs only to the immutable candidate fingerprint it ran against. Deployed proof additionally requires the exact Worker version and deployed configuration identity; source code or a local environment value cannot substitute for deployed truth.
