# 1.1 million Workers AI neurons in one day (2026-10-02)

## What customers saw

Nothing. The day's usage was about 100 times a normal day (4,000 to 28,000).

## Start and end (UTC)

2026-10-02, all day. Contained on 2026-10-07 by the per-run and per-day eval caps (0509#7249).

## Root cause

Not yet proven; strongest evidence. `evals.yml` ran 62 times on 2026-10-02 (33 successes, 21 failures, 8 cancelled), 31 of them from `pull_request` events, and each run made live Workers AI calls with no ceiling. Run-level neuron counts were not recorded, so the share of the 1.1 million that came from evals is an inference from the run count and the capped size of one run today (about 2,000).

## How it was detected

Read from the Cloudflare usage analytics on 2026-10-14. Nothing alerted.

## The fix

Already merged before this note: evals are dispatch-only, each run stops at 2,000 estimated neurons, and a run refuses to start when the day's total plus 2,000 would pass 9,000 (0509#7249). #7487 adds a weekly canary and an issue when an eval run fails.

## What stops a repeat

1. Code: the caps above, in `tests/evals/harness.ts`.
2. Alert, open: the account's only spend alerts are the two budget alerts on total monthly spend ($10 and $20), which email but never stop spend; there is no per-product alert. Cloudflare's own usage-based billing notification for Workers AI is the stock answer and needs one setting in the Cloudflare dashboard (Notifications, Usage Based Billing, Workers AI), which only Nish can make.
