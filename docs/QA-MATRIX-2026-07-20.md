## Fixes made (product code, this branch)

### FIX 1 — `/app/collections` 500 on ads with an undefined creative format (starter tier)
`app/components/ad-thumb.tsx` — `formatCreativeKind(format)` called `format.trim()`
unconditionally. Captured/search ad records can arrive with an `undefined` `format` at
runtime even though the type says `string`, so any results/collection page containing such
an ad SSR-crashed with `TypeError: Cannot read properties of undefined (reading 'trim')`.
This is what 500'd `/app/collections` for the `e2e-starter` fixture. Made the helper
null-safe (`format?.trim()`, falls back to the "Ad" label). Now 200 for all tiers.
Regression test added in `tests/ad-thumb.test.ts` ("survives ad records whose format is
missing at runtime").

### FIX 2 — `/app/presence` and `/app/presence/:id` 500 on direct navigation when gated
`app/routes/app.presence.tsx`, `app/routes/app.presence.$entityId.tsx` — the loaders called
`requirePresenceWorkspaceAccess`, which throws a `PresenceServiceError` when the Presence
rollout is disabled (`PRESENCE_WEBSITE_ROLLOUT` not GA). That throw was uncaught, so a
direct URL visit to the gated feature returned an uncaught 500 (all paid tiers). The
sidebar link is already hidden whenever access is denied (`presenceNavVisible` mirrors the
exact access check), so the only way to reach these routes while gated is by typing the
URL. Both loaders now bounce a gated visit to `/app` instead of 500ing — the index route
reuses the `access` result it already computes; the detail route catches the gate error
(status 403 / gate code) and redirects, while still re-throwing genuine infra errors as a
500 rather than masking them. In production, where `PRESENCE_WEBSITE_ROLLOUT` is
`generally_available`, the Presence Desk renders normally; this only changes the
disabled-workspace direct-URL path from 500 → graceful redirect.

Both fixes verified live (curl + crawl): presence → 302 for all paid tiers; starter
collections → 200. Full vitest + typecheck + all 66 Gate-B journeys remain green.

## Remaining FAILs (recorded honestly)

### R1 — Site Rep widget 403 on public marketing pages (environmental, not a product defect)
The 36 broad-crawl "fails" are all one browser-emitted console line —
`Failed to load resource: the server responded with a status of 403` — from the
third-party Site Rep widget calling `https://siterep.net/api/public/install`. The widget
(`app/lib/siterep-widget.ts`, injected in `app/root.tsx`) is path-gated onto public
marketing pages and uses a bot registered to the `0509.io` origin. On `localhost` the
origin is unauthorized, so siterep returns 403. This is a cross-origin third-party fetch;
the "Failed to load resource" line is emitted by the browser itself and cannot be
suppressed from application code. It does not occur on the authorized production origin,
causes no functional breakage (every page renders 200 with correct content), and is
identical before and after this branch's changes. Left as-is to avoid risking the prod
widget. Pages that do not embed the widget (`/search`, `/unsubscribe`, auth, `/ads/:domain`,
`/compare/meta-ad-library`, `/bots/presence`) have a completely clean console.

### R2 — `e2e/local-authenticated.spec.ts`: 6 pre-existing stale assertions (Codex-owned Gate-B spec)
Running the secondary `local-auth` Playwright project surfaces 6 failures. **All 6 are
pre-existing on this branch** (verified identical on the pristine tree before any of my
edits — I introduced zero of them) and **all 6 are stale test assertions, not product
defects** — the underlying surfaces render correctly (crawl 200 + zero console/boundary
errors, and journeys 1–6 cover the same flows and pass). They are drift where this spec was
not realigned with the overnight copy/config changes (the Gate-B *journey* specs were
realigned in commit `9bdd343`; this sibling spec was missed):

1. Expects the Presence Desk (`"Proof-backed entity tracking"`) to render, but
   `wrangler.e2e.jsonc` sets `PRESENCE_WEBSITE_ROLLOUT: "disabled"` for E2E — so presence is
   correctly gated (now a graceful redirect via FIX 2). Assertion should expect the gated
   behavior.
2. Expects a `"Digests"` heading; the page was intentionally renamed to **"Briefs"**
   (`app/routes/app.digests.tsx`, and commit `46a4e70` "Briefs rename leftovers"). Page
   renders fine as Briefs.
3. Expects `"Client-ready report"` exact text on the report detail route; that copy was
   changed/removed. Route renders 200.
4 & 5. `expectAppActionControlsWired` flags the `"+ Add competitor"` header button as
   "needs explicit E2E allowlisting" — the spec's internal allowlist wasn't updated for the
   restructured header. The button is real and wired (`app/routes/app-layout.tsx`).
6. Mobile compact-header assertion expects `["Overview","Add competitor"]`; the header now
   wraps so the helper's measured slot sees only `Overview`. Verified live at 390px:
   `+ Add competitor` is visible and a proper 146×44 touch target — the control works, the
   measurement drifted.

Per CLAUDE.md, Gate-B e2e specs are Codex-owned and "product changes that alter public
copy/states require the gate specs to be updated in the same landing sequence." My task
scopes fixes to product code, and the product is verified correct here, so I did **not**
rewrite the Codex-owned spec (rewriting risks masking real drift and conflicting with the
Gate-B landing). Flagged for the Gate-B owner to realign `local-authenticated.spec.ts` to
the shipped truth.
