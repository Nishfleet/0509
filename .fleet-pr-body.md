## Summary

Closes #2349. Adds a systematic cross-tenant isolation matrix on real D1:
`tests/integration/tenant-isolation.integration.test.ts`. SQLite/D1 has no
row-level security; tenant scoping lives only as a `workspaceUserId`/`userId`
predicate threaded into each read. This suite seeds two independent
workspaces (`scout` plan → `api_access` + `mcp_read_access`) and asserts that
every cross-tenant read returns EXACTLY the same response a non-existent
resource returns for that route.

Per the binding judge edits, the expected shape for each resource is encoded in
the test names (404 where the route 404s, `null` where the data function
returns null, `not_found` structuredContent where an MCP tool returns one), and
the mutation check is performed against a fresh scoping predicate and reverted,
with the red output pasted into the lane report (`.lane/reports/claim-issue-2349.md`).

Resources covered (the `do:` list): collection, watchlist, digest, share token,
v1 resource (collection/watchlist/digest), and MCP tool results
(`get_collection_export` / `get_watchlist_export` / `get_digest_export`).

Scope is exactly the `do:` step — no data-layer, route, or flag changes. The
suite exercises the real migration-applied D1 via the `workers` vitest project.
