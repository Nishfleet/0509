## Why

Anonymous `/search` used one global per-IP 20/10min bucket. A first-time evaluator behind an office NAT, or anyone sharing the VPS IP with fleet walks, could hit HTTP 429 on their first search. The only escape was "Sign in for more searches", which forced an account before any preview and broke the primary CTA.

## Scope

- `app/lib/rate-limit.server.ts`: stacked buckets. Per-browser 20/10min (`public-search-anon-browser`, cookie id via `keySeed`) plus per-IP abuse backstop 100/10min (`public-search-ip`). Signed-in searches still skip the anonymous limiter.
- `app/routes/search.tsx`: mint or reuse `f9_anon_search`, pass it into the limiter, Set-Cookie on a fresh success or 429, and put `continuePath` (`/auth/signup?redirectTo=...`) on the 429 JSON. The route `headers()` export forwards Set-Cookie and Retry-After only. It does not copy `Content-Type` from `Response.json()` onto the HTML document.
- `app/components/public-route-state.tsx`: honest 429 now has "Continue in a signed-in account (free)" as a reachable next action that does not require a pre-existing account. Sign-in remains as a secondary link.
- `scripts/search-latency-probe.mjs`: anonymous first-value canary. Fresh no-cookie GET of `/search?q=nike&country=all` with a dedicated user-agent, written to `first-value.csv`. `detectFirstValueRegression` fires at the start of a 3-window 429 streak.
- Tests for the limiter, the 429 continue path, cookie reuse, header forwarding, and the canary/edge detector.

Out of scope: migrations, workflows, verifier files. The existing `search-latency-regression-guard.mjs` CLI was left unchanged; its GH token wiring trips the local secrets guard on any edit, so the edge detector ships on the probe (same contract as `detectAuthRegression`).

## Tradeoffs

IP backstop is 100/10min, not 20. Cookie-stripping attackers share that ceiling. A first-timer on a busy NAT still gets a search unless the whole IP is actually abusive.

## Blast Radius

Anonymous `/search` only. Signed-in search, `/ads`, and `/timeline` are untouched. Fail-open on D1 hiccups is unchanged. The canary is one extra GET per probe run with its own user-agent, so it cannot fill the 100-slot IP backstop.
