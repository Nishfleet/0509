## reccos: Unify the triplicated env-rehydration in ad-source.server.ts (issue #2337)

Unifies `resolveCommercialDiscoveryEnv`'s four near-identical 15-field spread
blocks into one `mergeDiscoveryEnv(base, overlay)` helper plus a single ordered
resolution list. Adding a provider binding now means editing the
`DISCOVERY_MERGE_FIELDS` list once instead of four hand-copied blocks.

### What changed
- New `mergeDiscoveryEnv(base, overlay, { skipBrowserRunCredentials })` — one
  merge that applies the overlay's `??`-preference on every binding and skips
  Browser Run credentials for the raw BROWSERLESS-only request env (which has
  no Quick Actions / runtime signal backing them).
- `resolveCommercialDiscoveryEnv` now builds a single ordered `candidates`
  resolution list (request BROWSER binding → request Quick Actions → request
  BROWSERLESS-only → Worker runtime) and returns the first match merged once.
  The Worker-runtime entry resolves lazily (a last resort), so the
  `import("cloudflare:workers")` is not awaited on the common request-env hot
  path — matching the original's short-circuit.
- Behavior is byte-for-byte preserved: the same order and the same per-branch
  field handling (including BROWSER authority from the base env, guaranteed by
  the early `env.BROWSER` return, and the Browser-Run-credential omission only
  in the raw BROWSERLESS-only branch).

### Scope
`files:` + `do:` only — a single file, `app/lib/ad-source.server.ts`. No new
mechanism, script, or organ; no product copy.
