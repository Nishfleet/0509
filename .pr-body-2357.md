## Delete the spoofable `x-forwarded-for` fallback in rate-limit keying

Moves rate-limit identity keying onto Cloudflare's trusted `cf-connecting-ip`
only. The old `requestKeyHash` fell back to `x-forwarded-for[0]` — a
client-controlled value — so wherever `cf-connecting-ip` is absent (any future
front-door change; the env layer is proxy-aware for exactly this reason) an
attacker could spoof an unlimited number of rate-limit identities.

### Change (`app/lib/rate-limit.server.ts`)

- Drop the XFF branch entirely.
- When `cf-connecting-ip` is present, key as before (`<scope>|<ip>` for
  `keyByIpOnly`, else `<scope>|<ip>|<user-agent>`).
- When `cf-connecting-ip` is absent, key the request as `<scope>|unknown`
  with **no user-agent component**, per the judge edits. All headerless
  requests share one bucket regardless of any XFF or user-agent they carry,
  and the **existing per-policy cap then applies collectively** to that shared
  bucket.

This keeps `keySeed` (user-id / anonymous-browser-id) paths untouched.

### Acceptance

`accept: Unit test: requests with random spoofed XFF all share one bucket and hit the cap.`

Both new tests pass red on the old code and green on this change (verified by
running them against the pre-fix `requestKeyHash`).

Critical (must fix): none.

Review-adjudication:
- Consider — shared `unknown` bucket couples all IP-less clients per scope (20/10m for `auth`); a spoofing attacker could exhaust it and deny IP-less clients. Inert behind Cloudflare (`cf-connecting-ip` always present); strictly stronger than the old unlimited-identities behavior; the tradeoff is documented in the commit comment and matches the judge's binding edits. Kept as written (issue explicitly requires the shared bucket). Not re-delegated.
- Consider — nice-to-have test asserting IP-keyed and `unknown` keys stay in separate buckets. Noted; current tests prove both behaviors independently. Not acted on (kept minimal per issue scope).
- Noted — `sha256Hex` double-encode is pre-existing, not a regression.
- Noted — `keySeed` truthiness check is pre-existing; no caller passes an empty seed.
