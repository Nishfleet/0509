## What

Closes #1957. The public /timeline/:domain Offer Timeline rendered capture-retry bursts as several distinct "dated offer states" with empty transitions. `buildOfferLedger` (app/lib/offer-timeline.ts) emitted one ledger entry per stored snapshot, so the calendly page showed five "28 Aug 2026" rows (5 captures in 54 seconds) and adspyder showed three same-second captures as separate states.

This PR collapses consecutive snapshots that are identical in all four commercial fields (headline, ctaText, priceText, formPresent) into ONE dated state.

**Files**

- `app/lib/offer-timeline.ts` — `buildOfferLedger` now groups maximal identical runs and emits one collapsed state per run. The collapsed entry keeps the run's first capture's date and screenshot/page-text hrefs, carries a new nullable `runExtentLabel` ("unchanged since <date>"), and preserves a real before/after transition against the previous distinct state. `diffOffer` folded into `diffOfferBetweenStates` over the representative states; the commercial fields are uniform within a run, so comparing representatives yields the true change.
- `app/components/offer-timeline-ledger.tsx` — renders the `runExtentLabel` note under the state date when present.
- `tests/offer-timeline.test.ts` — new pure-function regression tests: calendly 5-in-54s burst collapses to 1, adspyder same-second collapse, real-transition preservation across a burst, mixed burst-then-change, and singleton no-extent.
- `tests/offer-timeline.render.test.tsx` / `tests/offer-timeline.route.test.ts` — `runExtentLabel: null` on the existing entry builders plus a render test asserting the collapsed state shows the "unchanged since" note as one row.
- `tests/ads-brand-page.render.test.tsx` / `tests/ads-brand-page.route.test.ts` — `runExtentLabel: null` on the OfferLedgerEntry test literals surfaced by the reviewer (typecheck).

Read-path logic only: no migrations, no D1/KV/R2 schema change, no `.github`/workflow/deploy/verifier path touched.
