Locale-prefixed programmatic /ads/:domain pages now serve 200 (issue #1562)

## What changed

The #1501 buyer-surface locale cluster added /de, /de/pricing, /de/help, …
but not the programmatic `/ads/:domain` Ad Aggression Score pages, so every
locale-prefixed brand page 404'd (`/de/ads/nike.com` -> 404) while the EN
`/ads/nike.com` served 200. A German or French buyer following the
sneaker-resale "Try the search preview" CTA to `/de/ads/nike.com` landed on a
dead route, blocking the BET 5 distribution bet for non-US search traffic.

- **`app/routes.ts`**: register `ads/:domain` under the `:locale` layout.
- **`app/routes/$locale.ads.$domain.tsx`** (new): re-export the EN
  `ads.$domain` route end to end (loader + meta + component) so the
  localised surface serves the SAME score page an EN visitor sees. The EN
  loader sets `canonicalPath` to `/ads/<domain>` (the EN route), so the
  re-exported meta points canonical→EN (accept #2) — duplicate content does
  not fragment search ranking.
- **`app/lib/locale-markets.ts`**: `buyerSurfaceLocaleForPathname` now
  recognises `ads/:domain` splats (a single non-slash domain segment), so
  `htmlLangForPathname("/de/ads/nike.com")` returns the locale lang (accept
  #3) and `canonicalPathnameForLocalePath` strips the prefix to `/ads/...`.
  A stray `/de/ads` (no domain) is still a 404 and keeps `lang="en"`.
- **`scripts/canary-locale-prefix-routes.lib.mjs`**: extend the locale-prefix
  canary (issue #1501) to probe `/ads/<domain>` for the four populated
  brands from the issue's verify block (nike.com, allbirds.com, nykaa.com,
  stockx.com) under every locale prefix. This is the mechanical prevention
  for the regression: a locale `/ads/:domain` page that stops serving 200
  now fails the canary, same as a missing core surface.
- Tests updated/added: canary probe surface (5×14=70 probes), locale lang +
  canonical for `/de/ads/...`, route registration + default-export re-export.

## Note on lang (accept #3)

Accept #3 asks for `<html lang="<locale>">`. On committed main the
`htmlLangForPathname` rule returns the locale lang for every recognised
locale buyer surface (the unconditional `BUYER_SURFACE_HTML_LANG` mapping,
including English-first surfaces like `/de/pricing`). This change follows
that established rule: `/de/ads/nike.com` reports `lang="de"`, matching the
rest of the cluster.
