## What this PR is

Closes the #3261 hole: only the aggregate `codex-node-checks` is a required context — `codex-node-checks-shard-2/3/4` are not (branch-protection contexts, observed 2026-09-13) — yet the aggregate job neither waited for nor observed its sibling shards, so #3336 merged 2026-09-13T02:30Z with `codex-node-checks-shard-4` FAILURE on its own PR, and every later PR could do the same.

Fix: the required `codex-node-checks` job gains one final step — "Fail if any sibling shard failed (aggregate, 0509#3261)". It polls the Checks API for the three sibling shard check-runs **of the same head SHA and the same Actions run** (a URL without this RUN_ID counts as pending, never as evidence — the previous attempt's completed check-run shadows a re-run otherwise) and fails the required context when any shard concludes non-success. A conclusion that never arrives fails closed at the 200m deadline (the 270m job cap bounds setup + own work + this wait; each heavy step's 180m lane-slot budget is what the 200m covers). No new check, no new workflow, no new job, no `continue-on-error`, and the never-conclude-skipped contract holds: no job-level `if:`, no `needs:`, the authorizer is still step 1.

Delta: one aggregate step in `.github/workflows/ci.yml` (+ a job-level `checks: read` permission), the regression test in `tests/required-context-no-skip.test.ts`, and — this round only — the drill file.
