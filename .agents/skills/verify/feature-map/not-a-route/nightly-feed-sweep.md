| nightly feed sweep | `workers/workflows/feed-sweep.ts` (the `FeedSweep` Workflow, binding `FEED_SWEEP`, exported as `FeedSweepWorkflow` from `workers/app.ts`), `app/lib/feeds/` and `app/lib/data/watch.server.ts` | no route — the `45 2 * * *` Worker cron (`triggers.crons`, `startScheduledWorkflow` in `workers/workflow-crons.ts`) creates one instance every night, id `feed-sweep-<YYYY-MM-DD>` | Content engine (0509#6377). Finds each brand's RSS or Atom feed (the homepage `<link rel="alternate">`, then `/feed`, `/rss.xml`, `/atom.xml`, `/blog/feed`, `/changelog.xml`), after `robots.txt` allows it, and files one `content` signal per post not seen before, with title, link and a short excerpt. Reads with a conditional GET (ETag and Last-Modified kept in `watch.config_json`), newest 20 posts under 30 days old, one retried step per brand and per feed; an unreadable or non-feed answer is "no feed" and fails nothing. A feed larger than 2 MB is read up to its first 2 MB instead of being refused; if nothing recent is found in that part (an oldest-first feed pushes its newest posts past the cut) the feed is `unreadable`, not "no new posts". The `feed.rss` source (`migrations/0037_feed_source.sql`, kind `site`, platform `feed`) shipped seeded disabled with `app/lib/coverage.ts` listing it `live: false`, so the Workflow planned nothing. The switch-on plan (recovered 0509#7165 from the deleted content engine packet's 'Going live' section in git history), now the shipped state: `migrations/0038_feed_pilot.sql` set `is_enabled = 1` with `config_json.pilot` at the soak account's email (`e2e+soak@0509.io`, `app/lib/fixture-accounts.ts`), and the same change flips `content.feed` to `live: true` in `app/lib/coverage.ts` — the coverage test requires a live entry and an enabled row to agree, both ways. `migrations/0050_feed_all_workspaces.sql` removed `pilot` once the soak report of 2026-10-08 showed vercel.com's feed read, so with no `pilot` key `readEntitiesWithoutFeedWatch` and `readFeedTargets` (`app/lib/data/watch.server.ts`, `IN_PILOT`) see every workspace's entities; setting `pilot` again in a data-only migration narrows the sweep to that account without a code change. Each night the Workflow runs at most 3000 brand lookups and 3000 feed reads (`app/lib/feeds/nightly-cap.ts`, under the 10,000-step instance limit); over that, the start of the list rotates by day so no brand starves, and `feed.sweep_capped` is logged with the totals. The off-switch is the same door: another data-only migration setting `is_enabled = 0`, with `content.feed` back to `live: false` in the same change. Proof: `tests/integration/feeds/` — the source row at `tests/integration/feeds/source-config.integration.test.ts`, the sweep at `tests/integration/feeds/sweep.integration.test.ts` |
