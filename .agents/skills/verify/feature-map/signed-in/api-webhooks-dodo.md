A valid one is recorded in `dodo_webhook_event` under its `webhook-id`, keeping only the event type, the subscription id and the timestamps (`payload_json` is that small object; no customer data is stored) (a redelivery of a processed id answers 200 and changes nothing). For `subscription.*` events it maps `product_id` to a plan through the `DODO_PRODUCT_*` vars and upserts the workspace's one `plan` row (`tier`, Dodo's `status` as sent, customer and subscription ids, `current_period_end` from `next_billing_date`); the workspace is the one whose plan row already holds that subscription id, else the checkout metadata's `workspace_id` but only when its `proof` (an HMAC of the workspace id and product id under `BETTER_AUTH_SECRET`, put there by `app/lib/billing/checkout-proof.server.ts` when our server creates the checkout) verifies; metadata with no or a wrong proof (a static payment link, a copied workspace id) is reported as `billing.webhook_unproven`, changes nothing and answers 200; once the workspace has a current subscription, an event for a different subscription is ignored whatever its tier, and a Tester-product event is ignored while the current subscription is still live (a tester checkout finished after buying a plan never downgrades it), unless it is a `subscription.active` strictly newer than the current row, so the end of an older plan cannot overwrite a newer one and a delayed or replayed `subscription.active` cannot flip the plan back. An event older than the row's `updated_at` does not overwrite it. An unknown product or a subscription body that cannot be read answers 200 but stays unprocessed, so the 36-hour stuck-event check reports it, and each is sent to Sentry as `billing.webhook_unknown_product` or `billing.webhook_unparsed` (200, so Dodo does not retry a body that can never apply and never disables the endpoint over it); a missing workspace answers 500 so Dodo retries it; a non-subscription event is recorded and changes no plan; a signed body that is not a Dodo event answers 200, is logged as ignored and stores nothing, so Dodo does not retry it.
