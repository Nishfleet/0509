## What

BET 5a (issue #1549): the programmatic `/ads/:domain` seed-list publisher.

A nightly pipeline turns curated seed lists into published `/ads/:domain` pages with the BET 2 gate: for every domain, run the exact search-v2 pipeline (country `all`, the scope every crawler lookup tries), classify the three tiers, and publish only when `verified + likely >= 1`. Unmatched-only or empty coverage is skipped and logged — no page ships empty (BET 5's gate).

How a publish happens: the publisher writes a `public_search` discovery-cache row under the exact search-v2 domain key the `/ads/:domain` loader derives. No further persistence is needed — the page renders from that row (`loadBrandPageCacheSnapshot`), the dynamic sitemap lists it (`loadIndexableBrandPageEntries`), and the sitemap response is server-rendered with `max-age=3600` so a new page appears to crawlers within an hour.

### Pieces

- `data/seed-lists/sneaker-resale.json` — the market-signal 2026-09-01 sneaker-resale cluster (issue #1547: "SneakerPing 59.5% below retail + high-engagement Nike demand thread") plus established sneaker/resale Meta advertisers (25 domains).
- `app/lib/ads-domain-publisher.server.ts` — publisher core: BET 2 gate (`shouldApplySearchV2` — a non-v2 rollout aborts before any provider call), per-domain exact search-v2 run, `verified+likely>=1` publish floor, `ads_domain_published` / `ads_domain_skipped` / `ads_domain_failed` / `ads_domain_publisher_run` observability events (console JSON, the repo's search-observability pattern), and a hard per-run domain cap (`ADS_DOMAIN_PUBLISHER_CAP`, default 60) bounding nightly provider spend.
- `workers/app.ts` — the publisher rides the existing 04:00 UTC daily cron (same rail as the demo-brand backfill). No new wrangler cron: a new one would escape the release-soak observation CHECK that accepts only the four production crons. Rollback = removing the block.
- `scripts/ads-domain-publisher.mjs` + `npm run seed:publisher` — the operator dry-run preflight for the issue's verify: probes production `/search` per seed domain (reusing the proven `parseSearchResponseHtml` / pacing from `scripts/bet2-live-verification.mjs`), applies the same publish floor, prints a per-domain report, exits 0 only when ≥15 domains would publish.
- `tests/ads-domain-publisher.test.ts` — pure verdict, seed-list validation, registry sanity (16 tests).

### BET 2 gate

The publisher observes the BET 2 gate in two places: at runtime (`SEARCH_ROLLOUT_MODE` must be `v2`, else the run aborts with `gate: bet2_inactive` — `SEARCH_ROLLOUT_MODE=v2` is the production posture in `wrangler.jsonc`), and the CI/live three-tier gate is the existing `npm run canary:bet2` which this PR does not touch. Production search is confirmed v2 by the live dry-run below (per-domain tier counts).

### Canary enforcement (#1455/#1454)

Those two issues own the always-on noindex-free/sitemap/search-link canary and the cross-link/BreadcrumbList canary respectively; they are open and their canaries land with those issues. This PR ships the pipeline those canaries watch.

research: compared reusing the existing production `/search` surface + `scripts/bet2-live-verification.mjs` parser (adopted — the proven BET 2 verification path, zero new scraping machinery) against an in-process provider invocation from a local script (rejected: the Browser Run binding and Meta API token exist only in the deployed Worker, so a local script cannot run the provider in-process) and against a new internal JSON API endpoint (rejected: an unauthenticated endpoint that triggers paid browser captures is an abuse vector; the production `/search` route already rate-limits anonymous traffic).
