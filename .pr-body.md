## seo: /brands hub emits an ItemList JSON-LD (one ListItem per tracked brand)

Issue #2215 — Google was reading /brands as a flat page because the route
only emitted WebPage/WebSite/Organization JSON-LD. This PR adds a schema.org
ItemList with one ListItem per tracked brand, each linking to its
`/ads/:domain` canonical URL, so Google can understand the page is a browsable
51-brand collection and connect the brand pages as a cluster.

### What changed

- `app/lib/seo.ts` — new `itemListJsonLd(entries)` helper. Each ListItem's
  `item` URL is derived from its pathname via the existing `canonicalUrl()`
  so the structured data can never drift from the site's canonical URL
  scheme; `name` matches the visible link label.
- `app/routes/brands.tsx` — the /brands route emits the ItemList JSON-LD
  alongside the existing WebPage JSON-LD. Built from the SAME loader brand
  list (`data.groups`), so no new data source and it can never drift from the
  visible links. Emitted only when brands are actually listed — an empty hub
  renders no ItemList.
- `tests/brands-route.render.test.tsx` — two new tests: one asserts a single
  ItemList with one ListItem per brand (correct position/name/item URL) and
  that the existing WebPage JSON-LD is unchanged; one asserts the ItemList is
  omitted when no brand pages are indexed.
