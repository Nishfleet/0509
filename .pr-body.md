## fix(activation): welcome email can never send — customer-lane dispatch gate requires a delivery_target the welcome claim never has

### Problem
`sendWelcomeEmail` claimed with `lane: 'customer'` and `deliveryTargetId: null`. The customer-lane dispatch gate in `markInstantDeliveryDispatchStarted` only advances a claim when a matching, validated, opted-in `delivery_target` row exists (`target.id = delivery_attempt.delivery_target_id`). With `deliveryTargetId: null` the join never matches, so every welcome claim is lost and leaves a stuck pending row that is reclaimed and re-failed on every later trigger. The WP-25 welcome email has never sent.

### Fix
In `sendWelcomeEmail`, before claiming, resolve or provision the verified account-email delivery target using the existing `resolveActivationEmailTarget` pattern already in this file, and pass its id as `deliveryTargetId`. If no target can be provisioned, return `{ sent: false, reason: 'target_unavailable' }` WITHOUT claiming, so no stuck pending row is left.

This is the durable, target-backed fix (it also supplies the unsubscribe link). No `templateName='welcome'` exception was added to the dispatch gate; the gate SQL and welcome copy are unchanged.
