## Why

Every other BET in the transformation campaign rests on a public claim being true, and a customer who hits a claim that is not true is worse off than if they had used their own AI. This PR closes the three loudest claim/reality gaps from BET 10 (issue #1278): the funnel-flag contradiction (config said ON, docs said NOT live), a release verdict in the positioning doc's header, and the retired ledger path that pointed at a file that never existed. It also ships the claim-by-claim audit table the issue asks for, with a mechanical verifier wired into the existing test job.

## Tradeoffs

- Flip-to-off instead of keep-on: clearing the §8 gates needs Nish (owner approval, legal/privacy review). The worker default in the issue text is to flip the flag off and file the re-enable follow-up, which it did (#1590).
- The verify commands are lightweight `grep -qF` source checks rather than re-running every mapped test file inside the script; the mapped tests still run in the normal suite (the audit-table test runs a live sample, the registry test runs CLAIM_CHECKS on every claim), so the script stays fast enough to spawn from inside a vitest test without doubling CI time.

## Blast Radius

- The funnel flag change is a single prod var; collection was already documented as NOT live, and the gate is off for any value other than 1/true/yes/on, so flipping `"1"` → `"0"` only stops a path that was never supposed to be on. Rollback is setting the var back to `"1"` (or reverting this PR).
- Docs and registry files are read by tests that pin their shape (registry SHA pin, audit-table test, verify-claims test) — all green in this run.
- No D1, Durable Object, KV, R2, migrations, workflows, or gate-owned paths touched.
