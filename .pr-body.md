Progressive first card on `/search` (BET 2, issue 1471): cold searches now render a tier-progress row ("N verified · M checking…") instead of a bare warming body, so the first visible result content always lands inside the 5s first-value budget while the cold verify pass keeps running in the background.

The `/search` loader already streams the synchronous tier it has — cached verified + likely rows on warm domains, the typed warming state on cold ones (cold path returns immediately, capture runs in `waitUntil`, partial cache entries paint mid-capture, the 2s warming poll swaps in the final write). What the first payload lacked was the tier itself: the warming body showed no counts and no regression test bound the <5s + no-navigation contract. This PR renders the tier the payload already carries and locks it with a stub test.

What changed:

- Cold first payload (no cached rows): the warming empty state now reads "`N verified · still checking — Usually under a minute — we'll refresh automatically.`" under the unchanged "Checking the Ad Library now" lead. A truly cold search says "0 verified" — a spinner-only body is gone, honest-empty copy intact (exhausted/retry and no-results states untouched).
- Partial first batch (rows already painted): the progress banner becomes the tier-progress row — "`N verified · M checking — loading more…`" — via the new pure `formatSearchTierProgressRow` in `app/lib/search-display.ts`. Legacy v1 results that carry no tier metadata keep the plain "N ads so far" wording byte-identical.
- No loader restructure: the cold verify pass, partial cache writes, and the 2s warming poll are untouched; the page still self-updates in place when the full result lands (React Router revalidation re-runs the loader, the mounted route updates, no re-mount).
- New stub test `tests/search-progressive-first-card.test.ts` mocks the `meta_library_browser` surface at the route-data channel: tier-1 (cached) rows resolve synchronously in the first loader payload; tier-2 (the live verify pass, ~15s in the field) lands later through the same channel a revalidation uses. It asserts (a) the first visible result row renders within 5s of mount and (b) the page self-updates when tier-2 lands without a `window.location` navigation or a full document reload (same mounted DOM node, navigate mock never called, href unchanged).
